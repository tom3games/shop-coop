# 仮の店（一人称の協力店舗ゲーム・試作）

一人称で店員になり、焼く・注ぐ・渡す・会計する。営業が進むほど客が増え、最後は全員で走り回る。
1〜4人。スマホ（縦・横）と PC のブラウザで遊べる。

店の種類はまだ決めていない。いまは「仮の店」と仮の商品（仮パン・仮ドリンク）で、どの店にも使える土台を確かめている段階。

## 遊び方

| | スマホ | PC |
|---|---|---|
| 歩く | 画面の左半分に指を置く（そこにスティックが出る） | WASD |
| 見回す | 画面の右半分をなぞる | クリックで視点を固定してマウス |
| 使う（持つ・置く・入れる・渡す・会計） | 右下の手のボタン | E / クリック / Space |
| 走る | 走るボタン（押すたびに入／切） | Shift（押している間）/ R で切り替え |
| 休憩 | 右上のメニュー | Esc |

- 仮パン: 生地箱から生地 → オーブン → ゲージが緑の間に取り出す（「よく焼き」はオレンジ）
- 仮ドリンク: カップ → ドリンク機に置く → 満タンで取る
- 客に渡す → 全部そろうとレジに並ぶ → 会計
- 生地箱が空になったら材料の箱を運んで補充（材料費がかかる）

## 起動

```
npm install
npm start            # http://localhost:8110
npm test             # ルールと部屋と通信のテスト（24件）
node tools/e2e.mjs   # 実ブラウザ（chromium と webkit）で3人つないで通しの営業
./publish.sh         # Cloudflare の無料トンネルで外に出す（URL は起動のたびに変わる）
./publish.sh stop
```

「ひとりで営業」はサーバーを使わずブラウザの中だけで動く（同じ部屋の仕組みをブラウザで動かしている）。

## 技術の選び方

| | 選んだもの | 理由 |
|---|---|---|
| 3D | Three.js r185（ブラウザ） | インストール不要でスマホでもすぐ遊べる。リンクを送るだけで友だちが入れる。ビルド工程なし |
| 通信 | Node.js + WebSocket（ws）、サーバーが正 | 客・注文・品物・設備の状態はサーバーだけが持つ。各画面は「何を使うか」だけ送る。食い違いが起きない |
| 自分の動き | 各画面で動かして位置だけ送る | 回線が遅くても歩きが重くならない。サーバーは壁と範囲だけ確かめる |
| 他の人と客 | 15回/秒の状態を 0.11 秒遅らせて補間 | 届く間隔のばらつきでがたつかない |
| モデル | 全部その場で組み立て（ファイルなし） | 読み込みが軽い。店の種類が決まったら差し替える |

比べて外したもの: Unity/Godot（ストアやインストールが要り、友だちを誘う手間が増える）、P2P の WebRTC（つながらない回線がある）、
有料のマルチプレイ基盤（月額がかかる）。

費用: 0円。公開は手元の Mac で動かしたサーバーを Cloudflare の無料トンネルで出している（Mac が起きている間だけ遊べる）。
常時公開するなら小さい VPS（月500〜1,000円程度）か Fly.io などに `npm start` を置くだけで動く。

## 構成

```
server.mjs                     画面と WebSocket を同じポートで出す
public/shared/sim.js           営業の共通の仕組み（客・注文・工程・品質・売上・時間帯・結果）。サーバーとブラウザで同じものが動く
public/shared/shops/prototype.js  店固有のもの（商品・設備と配置・焼き時間・注文の追加条件・出店場所・設備の改善）。店を変えるならここ
public/shared/rooms.js         部屋（ロビー→営業→結果、途中参加、切断と再接続）
public/js/game.js              一人称の画面（歩く・照準・使う・注文票・案内）
public/js/world.js             店の3D（設備・品物・人・吹き出し）
public/js/input.js / audio.js / net.js / save.js / main.js
tools/bot.mjs                  人と同じ操作だけで営業する自動店員（テストと調整用）
tools/e2e.mjs                  実ブラウザでの通し確認と、画面の収まりの数値確認
```

## いま入っているもの

- 作業の種類: タイミング型（オーブン）、手順型（ドリンク機）、運搬型（全部）、補充型（生地箱）、対応型（渡す・会計）
- 客: 来店 → 注文 → 待つ（顔と吹き出しで機嫌が変わる）→ 受け取り → レジ → 店で食べる／持ち帰り → 退店。待たせすぎると怒って帰る（渡した分は払っていく）
- 時間帯: 開店（1品・ゆっくり）→ 昼（2品の注文）→ ピーク（3品・「よく焼き」）→ 閉店前（新しい客は来ない）。新しい要素は1段ずつ
- 人数で客の量が変わる（1人でも4人でも回る）。途中参加できる
- 出店場所2つ（住宅街＝少なめ・よく焼き多め / 駅前＝多い・待たない・高い）
- 結果: 利益・売上・材料費・客数・成功率・平均品質・満足度・自己ベスト
- 設備の改善（店の貯金で買う）: オーブン2台目 / 早足の靴 / 大きい生地箱
- 案内（最初の2回の営業だけ）: 次にやることと、その場所を指す矢印
- 音: 注文・焼けた・焦げそう・ドリンク完成・渡した・会計・怒った・時間帯の切り替わり。BGM は忙しくなるとテンポが上がる

## 調整の余地（遊んでから決める）

- 1回の営業は 7分（指示書の目標は 15〜20分）。短いほうが試しやすいので、遊んだ感想で `createSim` の `duration` と `PHASES` を伸ばす
- 自動店員での目安（2人・住宅街）: 客19人中18人を会計まで、ピークの待ち客は序盤の約7倍。駅前は同じ2人で成功率8割
- 営業の途中で「続ける／やめる」を選ぶ区切りはまだ無い（時間で終わる）

## まだやっていないこと

- 店の種類の決定と、店固有の工程（例: 麺の硬さ）
- 物を投げる・落とすなどの物理
- 常時公開のサーバー（いまは手元の Mac から出している）
