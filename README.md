# ラーメン 仮屋（一人称の協力ラーメン屋）

一人称でラーメン屋の店員になり、麺を茹でて、スープを張って、盛って出す。食べ終わった丼を下げて洗い、レジで会計。
はじめは普通の一杯だけ。営業が進むと「硬め・柔らかめ」「味濃いめ・油多め」「味玉・チャーシュー追加」が1段ずつ増える。
1〜4人。スマホ（縦・横）と PC のブラウザで遊べる。

## 遊び方

| | スマホ | PC |
|---|---|---|
| 歩く | 画面の左半分に指を置く（そこにスティックが出る） | WASD |
| 見回す | 画面の右半分をなぞる | クリックで視点を固定してマウス |
| 使う（取る・入れる・盛る・のせる・出す・下げる・会計） | 右下の手のボタン | E / クリック / Space |
| 走る | 走るボタン（押すたびに入／切） | Shift（押している間）/ R で切り替え |
| 休憩 | 右上のメニュー | Esc |

1. 麺の箱（左の壁）から麺 → 茹で釜のてぼへ。ゲージは 青=硬め / 緑=普通 / オレンジ=柔らかめ / 赤=のびた。茹で上がりが近づくと湯気が増えて音が鳴る
2. 丼置きから丼 → 寸胴でスープ。「味濃いめ」はかえし、「油多め」は背脂を足す
3. スープの入った丼を持って茹で釜を使うと麺が入る → ネギ（と注文のトッピング）をのせる
4. カウンター越しに客へ出す → 客がその席で食べる → 席に丼が残る（下げるまで次の客は座れない）→ 洗い場で洗うと丼置きに戻る
5. 食べ終わった客はレジに並ぶので会計。麺の箱が空になったら右奥の在庫を運んで補充（材料費がかかる）

失敗は減点で済む: のびた麺・硬さ違い・味の指定違い・トッピング忘れは点が下がり、客の顔とひとこと（「のびてる…」「かたっ」「味玉は？」）が変わるだけ。待たせすぎた客は怒って帰るが、出した分は払っていく。

## 起動

```
npm install
npm start            # http://localhost:8110
npm test             # ルール・ラーメン屋の工程・部屋・通信のテスト
node tools/e2e.mjs   # 実ブラウザ（chromium と webkit）で3人つないで通しの営業＋画面の収まり
node tools/tour.mjs  # 見た目の確認用スクショ（SIZE=844x390 TOUCH=1 BR=webkit で変える）
./publish.sh         # Cloudflare の無料トンネルで外に出す（URL は起動のたびに変わる）
./publish.sh stop
```

「ひとりで営業」はサーバーを使わずブラウザの中だけで動く（同じ部屋の仕組みをブラウザで動かしている）。

## 技術の選び方

| | 選んだもの | 理由 |
|---|---|---|
| 3D | Three.js r185（ブラウザ） | インストール不要でスマホでもすぐ遊べる。リンクを送るだけで友だちが入れる。ビルド工程なし |
| 通信 | Node.js + WebSocket（ws）、サーバーが正 | 客・注文・品物・設備の状態はサーバーだけが持つ。各画面は「何を使うか」だけ送る。食い違いが起きない |
| 自分の動き | 各画面で動かして位置だけ送る | 回線が遅くても歩きが重くならない。サーバーは壁と範囲だけ確かめる |
| 他の人と客 | 15回/秒の状態を 0.11 秒遅らせて補間 | 届く間隔のばらつきでがたつかない |
| モデル | 全部その場で組み立て（ファイルなし） | 読み込みが軽い。店の種類が決まったら差し替える |

比べて外したもの: Unity/Godot（ストアやインストールが要り、友だちを誘う手間が増える）、P2P の WebRTC（つながらない回線がある）、
有料のマルチプレイ基盤（月額がかかる）。

費用: 0円。公開は手元の Mac で動かしたサーバーを Cloudflare の無料トンネルで出している（Mac が起きている間だけ遊べる）。
常時公開するなら小さい VPS（月500〜1,000円程度）か Fly.io などに `npm start` を置くだけで動く。

## 構成

```
server.mjs                     画面と WebSocket を同じポートで出す
public/shared/sim.js           営業の共通の仕組み（店員の持つ・置く、補給所、ゴミ箱、レジ、席、客、注文の受け渡し、売上、時間帯、結果）
public/shared/shops/ramen.js   ラーメン屋の決まり（茹で釜・寸胴・かえし・背脂・トッピング・丼・洗い場の動き、茹で時間と品質、注文の作り方、配置、時間帯、出店場所、設備の改善）
public/js/shops/ramen-view.js  ラーメン屋の見た目（設備の形・のれん・提灯・短冊・湯気・丼・注文の絵・案内）
public/shared/rooms.js         部屋（ロビー→営業→結果、途中参加、切断と再接続）
public/js/game.js              一人称の画面（歩く・照準・使う・注文票・案内）
public/js/world.js             店の3D（設備・品物・人・吹き出し）
public/js/input.js / audio.js / net.js / save.js / main.js
tools/bot.mjs                  人と同じ操作だけで営業する自動店員（テストと調整用）
tools/e2e.mjs                  実ブラウザでの通し確認と、画面の収まりの数値確認
```

## いま入っているもの

- 作業: タイミング型（茹で釜）、補充型（麺の箱）、手順型（スープ→味→麺→トッピングの順番）、運搬型、対応型（出す・下げる・洗う・会計）
- 客: 来店 → 席が空いていなければ待ち椅子 → 席で注文 → 待つ（顔と吹き出しで機嫌）→ 受け取って食べる → 席に丼を残してレジ → 会計 → 退店
- 時間帯: 開店（普通だけ）→ 昼前（麺の硬さ）→ 昼（味濃いめ・油多め）→ ピーク（トッピング追加）→ 閉店前（新しい客なし）
- 人数で客の量が変わる（1人でも4人でも回る）。途中参加できる
- 出店場所2つ（住宅街＝少なめで指定が多い / 駅前＝多くて待たない・高い・普通が多い）
- 設備の改善（店の貯金で買う）: 茹で釜2口目 / てぼの追加（3玉）/ トッピング台を作業台の前へ寄せる / 丼を増やす / 厨房用の靴
- 結果: 利益・売上・材料費・客数・出した杯数・成功率・一杯の出来・満足度・自己ベスト
- 案内（最初の2回の営業だけ）: 次にやることと、その場所を指す矢印
- 音: 注文・茹で上がり（硬めと柔らかめは短く、普通は長く）・のびた・湯切り・スープ・刻む・洗い上がり・会計・怒った。BGM は和風の刻みで、忙しくなるとテンポが上がる

## 調整の余地（遊んでから決める）

- 1回の営業は 7分（指示書の目標は 15〜20分）。`createSim` の `duration` と `PHASES` で伸ばす
- 自動店員での目安（同じ人の速さ・迷いなし）: 住宅街2人で客24人中21人、駅前2人で35人中25人を会計まで。ピークの待ち客は開店直後の約5〜15倍
- 営業の途中で「続ける／やめる」を選ぶ区切りはまだ無い（時間で終わる）
